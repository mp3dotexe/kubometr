# Kubometr

AI-консультант строительного магазина, разработанный на Go.

Kubometr — бэкенд-сервис для строительного магазина: принимает сообщения через мессенджер (Telegram, с миграцией на MAX Messenger), с помощью AI помогает подбирать материалы и консультирует по вопросам ремонта. История диалогов и пользователи хранятся в PostgreSQL. Приложение контейнеризировано и запускается через Docker Compose.

Проект развивается как коммерческий backend с постепенным добавлением REST API и интеграции с 1С:УНФ (каталог товаров, цены, остатки, заказы).

## Возможности

- Консультации через Telegram (миграция на MAX Messenger — в процессе)
- Интеграция с AI через OpenRouter (легко заменяемый провайдер)
- История диалогов в PostgreSQL
- Ограничение количества и параллельности AI-запросов
- Ограничение длины сообщений
- Таймауты запросов к AI
- Управление состоянием пользователя
- Разделение транспортного слоя и бизнес-логики (Service Layer, Repository Pattern)
- Юнит-тесты с моками через интерфейсы (dependency injection)
- Docker / Docker Compose для локального запуска (приложение + PostgreSQL)

## Запуск проекта

### Вариант 1 — через Docker Compose (рекомендуется)

1. Клонировать репозиторий:
```bash
git clone https://github.com/mp3dotexe/kubometr.git
cd kubometr
```

2. Создать `.env` (используйте `.env.example` как шаблон) — переменные `POSTGRES_*` не обязательно совпадать с локальными, Compose поднимает свой контейнер PostgreSQL.

3. Запустить:
```bash
docker compose up --build
```

Приложение будет доступно на `localhost:8080`, PostgreSQL — на `localhost:5433` (проброшен на нестандартный порт хоста, чтобы не конфликтовать с локальной установкой PostgreSQL).

### Вариант 2 — локально, без Docker

1. Клонировать репозиторий и создать `.env`, как выше.

2. Применить миграции — на данный момент вручную, выполнив SQL-файлы из `migrations/` (например, через `psql` или DBeaver) в порядке возрастания номера. Переход на `golang-migrate` — в планах.

3. Запустить:
```bash
go run ./cmd/bot
```
